3D printers are widely available tools for easily creating 3D objects.
Part development, however, still requires knowledge of 3D modelling in CAD software.
For this project, we explore how an agentic setup can contribute to the automatic development of these models.
The agent takes in a user request as text, determines the scope of the request (an "organic" shape versus a mechanical part) and attempts to generate a valid STL at the correct dimensions.
Mechanical parts use CadQuery code; organic shapes either use signed distance functions for sculpting or an optional download from the Thingiverse web service.
We show the architectural effects of gating, retrieval, and repair loops on this system.
We then compare multiple local and API-driven large language models (LLMs) as the orchestrators.
We use dimension bounding and an LLM-as-judge approach on a synthetic dataset of 78 cases ran in multiple configurations (2118 total runs), showing that smaller models exhibit better accuracy when using them.
Larger "frontier" models may exhibit improvements, but the agentic workflow has less variance on their overall performance.
